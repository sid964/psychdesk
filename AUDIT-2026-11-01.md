# PsychDesk repository audit — 1 November 2026

## Scope and approach
Reviewed the full GitHub repository tree, application entry points, account storage and Firebase synchronization, optional Drive backend, notes/Ink Notes/Sticky Notes, library uploads, PDF reader, reference and research flows, psychology glossary, timeline, mind maps, service worker, styling, and the test workflows.

Reproduced and covered concrete failures using Node tests and an automated Chromium audit at **320, 360, 390, 768 and 1440 CSS-pixel viewport widths**. The local browser audit exercises the actual static app, including navigation, ink handwriting, undo/redo, save on modal transitions, and recovery from unreadable local JSON. A separate **read-only** browser pass visits the public GitHub Pages deployment. No authenticated user's private study content, Google Drive, or Firebase console is accessed by the tests.

## High-priority findings and resolutions

| Area | Confirmed problem | Fix |
|---|---|---|
| Account-local storage | A corrupt account JSON record could be replaced with blank starter data on account switch | Preserve raw original, block overwrites, offer a raw JSON download and explicit recovery step |
| Startup recovery | A malformed startup snapshot could be treated as empty workspace | Detect and protect the original, display a visible recovery warning |
| Backups | `replaceData` could change in-memory data even when saving failed | Atomic replacement with rollback and explicit error |
| Notebook | A failed autosave could still clear the recovery draft, and changing dialogs could drop pending writing | Roll back failed writes, retain drafts, flush editor on dialog replacement |
| Quick capture | Failed notebook or sticky saves still cleared the draft and closed the editor | Retain draft and form; rollback new objects |
| Sticky Notes | Autosave failure still reported success | Restore original collection and keep the pending text |
| Firebase sign-in | Invalid guest JSON or failing browser storage could interrupt account initialization | Guard reads/writes and preserve original guest record |
| Firebase realtime | Remote revision could advance before the incoming data was saved locally | Commit the local snapshot before recording the new revision |
| Reference Manager | Save and batch import could show success without persisting | Preserve modal inputs/import preview and roll back |
| Academic and Wikipedia lookup | Failed writes could still report saved concepts, references or flashcards | Roll back new entries, warn visibly |
| PDF annotations | Failed highlight save could leave a phantom in-memory annotation | Remove the unsaved new highlight without discarding the selection |
| Study tools | Voice notes, generated flashcards and research forms could claim success on failed saves | Restore original data and keep user input |
| Subject library | A Drive upload could finish while the library metadata save failed, prompting a duplicate upload on retry | Preserve the completed upload result and retry only local metadata creation |
| Subject colors | Imported subject color strings were rendered as unchecked CSS styles | Restrict rendered colors to six-digit hexadecimal values |
| Cached code | Old service-worker/app assets could keep known bugs after deployment | Bump the app-shell cache and changed module URLs |

## Existing protections validated

- No handwritten ink, notes, previous study records, PDF source files or imported dictionary terms are deleted by this audit.
- Original nested-array Firestore snapshot fix remains intact.
- Existing per-account Firestore security rules and optional backend-based Google Drive OAuth are not weakened.
- Previous handwritten notes and user backups continue to use the current data schema.
- No Gemini/ChatGPT tutor, exam simulator, offline study module, or new paid service has been introduced.
- AMOLED/light styles preserved; the only additional on-screen interface is an error-recovery section that appears if local data is damaged.

## Remaining boundaries / owner-only verification

1. **Actual user account sync:** Node mocks confirm transaction behavior, but this audit does not read or modify private Firestore documents. After deployment, verify that a real note and one handwritten page sync between two signed-in devices.
2. **Google Drive long-term authorization:** The secure Cloud Functions refresh backend is still disabled in public Firebase configuration. Browser-only tokens cannot be made permanent on Firebase Spark without an alternative secure backend. Do not move refresh tokens into cookies, localStorage or public GitHub.
3. **Browser/hardware variance:** Chromium smoke tests do not prove ASUS stylus driver pressure behavior, Brave-specific Google popup blocking, Safari/WebKit, or Android background app eviction.
4. **Dictionary accuracy:** Wikipedia lookup is general reference, not a substitute for vetted academic sources. Europe PMC/OpenAlex rate limits and user-network conditions still apply.
5. **Storage limits:** Large editable handwriting and study snapshots can still exceed Firebase account limits. The app should display explicit sync errors and prompt users to export large material rather than silently truncating it.
6. **Unbounded feature expansion:** The app has many independent modules. The audit focuses on high-risk failures and major navigation/layout regressions, not a mathematical guarantee of zero defects in every third-party API or device configuration.

## How to verify

- Run `node --test tests/*.test.mjs` for account, persistence, notes and study features.
- Run the dictionary workflow's listed `node --test` command and syntax checks.
- Run the **PsychDesk browser and visual audit** GitHub Action for local Chromium and read-only live screenshots. Inspect its artifact for layout and console errors.
- After GitHub Pages updates, export a safety backup, create a test note, refresh the same browser tab, and confirm the note remains. Check Firebase sync status before testing another device.
- If you encounter a local corruption banner, first download the raw recovery file. Do **not** reset the account or force cloud overwrite to resolve it.

This report describes tested code behavior and known limits; no access to user secrets or private content was needed.
